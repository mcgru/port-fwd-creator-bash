# port-fwd-creator.sh

Один самодостаточный bash-скрипт, который настраивает постоянный SSH-туннель
между двумя хостами. Запускается с управляющего хоста (ноутбука): сам ходит
по ssh на оба конца, готовит ключ и authorized_keys, заполняет known_hosts,
создаёт юнит systemd --user или файлы openrc, проверяет проброс порта и
печатает памятку для root, готовую к копированию.

Скрипт не выполняет привилегированных действий: ни sudo, ни записи в /etc,
ни loginctl enable-linger, ни правки sshd_config. Всё, что требует root,
выводится в конце готовыми командами.

## Требования

- Управляющий хост: bash 4+, клиент OpenSSH (ssh, ssh-keygen), coreutils,
  getopt из util-linux.
- SSH-доступ с управляющего хоста до обоих хостов (ключи, агент или алиасы
  в ~/.ssh/config).
- host1: пользовательский аккаунт и systemd --user (по умолчанию) либо openrc.
- host2: sshd.

Сам ~/.ssh/config скрипт не разбирает: он спрашивает ssh -G, поэтому алиасы,
порты, пользователи и ProxyJump работают для контроллера как обычно. В сервис
попадают канонические hostname и port: на host1 конфига ноутбука нет.

## Формат адреса

```
[user@]host[:ip]:port
```

- ip1:port1 описывает сторону host1, ip2:port2 — сторону host2.
- Пустой IP означает 127.0.0.1: host2::8080.
- IPv6 пишется в скобках: host1:[::1]:8080.
- SSH-соединение всегда инициируется с host1 на host2. Направление решает
  только, кто слушает порт:

| Направление | Токены | Слушает |
|---|---|---|
| -L, -l, --local (по умолчанию) | >, >>, >>>, }, }}, }}} | host1 |
| -R, -r, --remote | <, <<, <<<, {, {{, {{{ | host2 |

Токены с > в шелле обязательно брать в кавычки, иначе это редирект.

## Быстрый старт

```bash
git clone https://github.com/mcgru/port-fwd-creator-bash.git
cd port-fwd-creator-bash
chmod +x port-fwd-creator.sh

# слушать на host1 в 127.0.0.1:18080, проброс на sshd host2
./port-fwd-creator.sh sss:127.0.0.1:18080 -L ttt:127.0.0.1:22

# то же с токеном направления
./port-fwd-creator.sh sss:127.0.0.1:18080 '}}}' ttt:127.0.0.1:22

# слушать на host2 в 172.17.0.1:3333, проброс на sshd host1
./port-fwd-creator.sh sss:172.17.0.1:22 '{{' ttt:172.17.0.1:3333

# явные пользователи, пустой IP -- это loopback
./port-fwd-creator.sh smelov@sss::8080 '>>>' tun-user@ttt::22

# на host1 openrc вместо systemd
./port-fwd-creator.sh ggg::18080 '}}}' hhh::22 --openrc
```

После успешного запуска туннель оформлен на host1 как включённый сервис,
а скрипт печатает памятку для root (linger для systemd, установка файлов для
openrc) и точную ssh-команду, которой пользуется сервис.

## Частые задачи

```bash
# посмотреть, что будет сделано, не трогая хосты
./port-fwd-creator.sh sss::18080 -L ttt::22 --dry-run

# настроить ключ, authorized_keys и known_hosts, но сервис не создавать
./port-fwd-creator.sh sss::18080 -L ttt::22 --no-persist

# проверить готовый туннель, ничего не меняя
./port-fwd-creator.sh sss::18080 -L ttt::22 --check

# снять сервис (строка ключа в authorized_keys остаётся)
./port-fwd-creator.sh sss::18080 -L ttt::22 --teardown

# показать успешные создания
./port-fwd-creator.sh --history

# в агенте много ключей -- фиксируем ключ контроллера
./port-fwd-creator.sh sss::18080 -L ttt::22 -K ~/.ssh/id_ed25519

# доп. опции ssh для туннеля (каждая станет своим -o)
./port-fwd-creator.sh sss::18080 -L ttt::22 -o 'Compression=yes ServerAliveInterval=15'

# своё имя сервиса и свой ключ на host1
./port-fwd-creator.sh sss::18080 -L ttt::22 -n my-tunnel -k ~/.ssh/id_tunnel
```

### Адреса через опции

--from и --to принимают тот же адрес [user@]host[:ip]:port и сильнее
позиционных аргументов: если заданы и аргумент, и опция, побеждает опция.

```bash
# без позиционных аргументов вообще
./port-fwd-creator.sh --from sss:127.0.0.1:18080 --to ttt:127.0.0.1:22 -L

# недостающую сторону можно оставить аргументом
./port-fwd-creator.sh --from sss::18080 ttt::22 -L
./port-fwd-creator.sh sss::18080 --to ttt::22 -L

# опция перекрывает аргумент: host2 здесь ttt:22, а не 9.9.9.9:22
./port-fwd-creator.sh sss::18080 -L ttt:9.9.9.9:22 --to ttt:127.0.0.1:22
```

### Повтор успешного запуска: --run

--run MOMENT смотрит history.success с конца файла и берёт первую запись,
у которой совпадает время (дата не участвует). Двоеточия убираются, время
приводится к целому, и от него с конца отсекается столько цифр, сколько их
в MOMENT:

```text
--run 59      любой запуск, у которого секунды 59
--run 4459    минуты и секунды 44:59
--run 24459   часы, минуты и секунды 02:44:59
```

Историческая команда восстанавливается и запускается заново, а текущие опции
накладываются сверху и побеждают исторические:

```bash
# повторить самый свежий успешный запуск с секундами 59
./port-fwd-creator.sh --run 59

# повторить его, но слушать на другом адресе/порту host2
./port-fwd-creator.sh --run 59 --to ttt:172.17.0.1:4444 --no-persist

# повторить с противоположным направлением
./port-fwd-creator.sh --run 59 -L
```

Перед реальными действиями скрипт печатает найденный момент и итоговую
команду и спрашивает:

```text
Run? [Y/n]
```

Enter, y или yes запускают; n, любой другой ответ или Ctrl+D отменяют без
запуска и без записи в историю; Ctrl+C прерывает. С --dry-run и --check
подтверждение не спрашивается, потому что ничего не меняется. Без терминала
(stdin не tty) повтор отклоняется с кодом 1.

### Повтор N-й с конца записи: --last

--last N берёт N-ю с конца запись history.success, а не ищет по времени:
1 (или 0) -- последняя, 2 -- предпоследняя и так далее; отрицательное N
считается положительным. Остальное как у --run: текущие опции перекрывают
исторические, печатаются время записи и итоговая команда, а перед реальным
запуском задаётся вопрос Run? [Y/n].

```bash
# последний успешный запуск
./port-fwd-creator.sh --last 1

# предпоследний, без создания сервиса
./port-fwd-creator.sh --last 2 --no-persist

# то же, что --last 3
./port-fwd-creator.sh --last -3
```

--run и --last взаимоисключающие.

Позиционные адреса вместе с --run или --last не принимаются: для перекрытия
есть --from и --to.

## Что делает скрипт

1. Разбирает аргументы через getopt, отвергает конфликты направлений и
   менеджеров сервисов.
2. Канонизирует оба хоста через ssh -G.
3. Определяет менеджер сервисов на host1 до любых изменений; при
   несовпадении падает и печатает ту же команду с нужным флагом в конце.
4. host1: берёт ~/.ssh/id_ed25519 или создаёт его (ed25519, без пароля).
   Публичная часть живёт только в памяти.
5. host2: whoami, поиск ключа в authorized_keys по телу. Если строки нет,
   дописывает restrict,port-forwarding,permitopen|permitlisten="ip2:port2".
   Своя строка (комментарий port-fwd-creator:...) обновляется при смене правила;
   чужая с другими опциями -- ошибка, пока не дан --force.
6. host1: первым коннектом на host2 заполняет known_hosts.
7. Собирает ssh-команду: -N -T, BatchMode, ExitOnForwardFailure,
   StrictHostKeyChecking=yes, явные ключ и known_hosts, IdentitiesOnly,
   keepalive каждые 30 с, пользовательские -o идут первыми (могут
   переопределить дефолты).
8. Создаёт сервис (если не задан --no-persist) и проверяет, что порт
   слушается именно на запрошенном адресе, а не просто на порту.
9. Печатает памятку для root блоками, готовыми к копированию.

## Персистентность

### systemd --user (по умолчанию)

- Юнит: ~/.config/systemd/user/<name>.service
- systemctl --user enable и systemctl --user restart выполняются от
  пользователя host1.
- Чтобы сервис жил после выхода и перезагрузки, root должен выполнить
  loginctl enable-linger <user>. Без linger юнит останавливается при
  закрытии последней сессии и поднимается при следующем входе.

### openrc

- Скрипт только готовит файлы в ~/.local/share/<name>/init.d и conf.d;
  в /etc он не пишет.
- Root устанавливает их и включает сервис:

```bash
install -m 755 ~/.local/share/<name>/init.d/<name> /etc/init.d/<name>
install -m 644 ~/.local/share/<name>/conf.d/<name> /etc/conf.d/<name>
rc-update add <name> default
rc-service <name> start
```

## История

На управляющем хосте, в ~/.local/share/port-fwd-creator/
(или $XDG_DATA_HOME/port-fwd-creator/):

- history.run -- каждый запуск, включая ошибки и прерывания;
- history.success -- только успешные создания: ok, когда сервис systemd
  запущен и порт реально слушается; prepared, когда файлы openrc готовы и
  ждут root.

В обоих файлах хранится полная командная строка с направлением,
нормализованным до -L/-R. --history печатает history.success; --run читает
его же.

## Особенности и ограничения

- Для -R на не-loopback адрес в sshd_config host2 нужен
  GatewayPorts clientspecified (root). Без него sshd принимает запрос, но
  привязывает порт к 127.0.0.1; скрипт сообщает о несовпадении адреса и
  подсказывает про GatewayPorts.
- permitopen ограничивает только -L, permitlisten -- только -R. В строке
  также включён port-forwarding в целом, поэтому строка, написанная для
  одного направления, не ограничивает другое.
- Ключ на host1 с паролем отвергается: сервис не сможет его разблокировать
  без агента.
- Ключ по умолчанию общий (~/.ssh/id_ed25519). Для отдельного туннеля
  используйте -k.
- --teardown убирает сервис, но оставляет строку в authorized_keys: ключ
  может быть общим.
- ProxyJump, заданный для host2 на ноутбуке, на host1 не применится; скрипт
  об этом предупреждает.
- Скрипт не ставит пакеты, не создаёт пользователей и не правит sshd_config.
